## 4. ★ 这个网页怎么改（重点）

前端文件在仓库 `Vansinver/info-radar/frontend/`：
- `index.html`（页面结构与内联样式）
- `history.js`（历史/会话状态机）、`auth.js`（登录/访客态）、`config.js`（`window.API_BASE=""` 表示同源）

标准流程：
1. 在 GitHub 改 `frontend/*`（有仓库权限的 Agent 可直接提交；`API_BASE` 必须保持空串）。
2. 服务器一键更新：
   ```bash
   ssh root@47.97.204.93 'bash /opt/info-radar/redeploy.sh'
   ```
   等价于：`cd /opt/info-radar/repo && git fetch --prune && git reset --hard origin/main && systemctl restart info-radar`
3. 打开 http://47.97.204.93/ 验证。

约束：
- 前端**不得**依赖 `127.0.0.1 / localhost / 本机路径`，否则线上直接崩。
- 改前端不影响数据；改后端 `server.py` 也要重启服务。
- 访客/owner 的数据分支在 `server.py`（guest→demo_data；写操作要 owner JWT）。

## 4b. E1 引擎怎么跑（已可用）

- 入口：登录 owner 后 `POST /api/jobs/e1`，body `{"query":"...","session_id":"可选"}` → 返回 `job_id`
- 后端实际执行：`/opt/info-radar/venv-gptr/bin/python run_e1.py <query>`
- 日志：`/data/joblogs/<job_id>.log`
- 产物：`/data/reports/YYYYMMDD_HHMM_<标题>.md`，含“## 来源清单”
- 实测：约 20–60 秒；成本约 ¥0.1–0.2/份；2G 内存可跑（used≈680MB + swap）
- 注：报告正文默认是**英文**（gpt-researcher 跟随模型语言）；用户已确认英文可接受，不要为此大改

## 4c. 备份与恢复

- 每日 04:00 cron：`tar /data` → `/data/backups/data_YYYYMMDD_HHMM.tar.gz`，保留最近 7 份
- 恢复：`tar xzf <备份> -C /data` → `systemctl restart info-radar`
- 局限：快照和数据在同一块云盘，**不是离站备份**
