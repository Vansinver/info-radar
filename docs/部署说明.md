# 公网部署说明与验收口径

## 0. 共同设计（两方案 90% 通用）
- 前端：本仓库 `frontend/`，经 `.github/workflows/pages.yml`（configure-pages enablement 自动启用）发布到
  `https://vansinver.github.io/info-radar/`。相对路径 + `config.js` 注入 `API_BASE`/`BUILD_VERSION`。
- 后端：`backend/server.py`（FastAPI）。端口 `PORT`（HF=7860）、数据目录 `DATA_DIR`、解释器 `PY_GPTR/PY_STORM` 全环境驱动。
- 认证：`OWNER_USERNAME/OWNER_PASSWORD/JWT_SECRET`（平台 secrets）。登录发 7 天 JWT，前端 localStorage 存令牌、Bearer 头发送。
- 持久化：`cloud_store.py` 启动 pull、写后 push、45s 周期兜底；排除 `.env`。
- 密钥转移：DeepSeek key 与所有者凭证经私有通道从本机 `.env` 程序化注入平台 secrets，**绝不进聊天/仓库**。

## 1. Plan A（主方案）：Hugging Face PRO + Docker Space
成本依据（官方复查）：
- 新建运行算力的 Space（Gradio/Docker）需付费 plan；Static 免费但无算力。
- PRO **$9/月**（约 ¥65）含 Host Docker Spaces；CPU Basic 硬件（2vCPU/16GB/50GB）**无小时费**。
- 免费 cpu-basic **48h 不活动休眠**，访客访问自动唤醒（冷启动约 1–2 分钟）；数据在私有 dataset，休眠不丢。
- 依据：https://huggingface.co/docs/hub/spaces-gpus 、https://huggingface.co/pricing
步骤：
1. 用户登录/注册 HF（需用户参与），订阅 PRO（需用户参与，$9/月）。
2. 创建私有 dataset `vansinver/info-radar-data`；把本机业务数据（reports/discussions/solutions/taskcards/legacy）推入。
3. 创建 Docker Space `vansinver/info-radar`，推送 `Dockerfile/entrypoint.sh/backend/`，`hf-space-README.md` 作为 README.md。
4. Space Settings 配置 secrets（变量名见 `.env.example`）：DEEPSEEK_API_KEY、OWNER_*、JWT_SECRET、HF_TOKEN、HF_DATASET_REPO、PAGES_ORIGIN、BUILD_SHA。
5. 等 Space 构建+启动成功，`/api/health` 返回 ok；注入 `frontend/config.js` 的 API_BASE=Space URL，推送触发 Pages。
6. 真实引擎端到端：跑一次低成本 E1 报告（约 0.1–0.2 元）验证检索+成文+落盘+同步。
预期 URL（部署后才是真实）：后端 `https://vansinver-info-radar.hf.space`，前端 `https://vansinver.github.io/info-radar/`。

## 2. Plan B（零成本备选）：Oracle Always Free ARM + Tailscale Funnel
- Oracle 永久免费 ARM（4 核 24GB），需用户现有 Visa/万事达卡验证（不扣费）；风险=A1 容量短缺/注册摩擦。
- Tailscale Funnel 免费 HTTPS（`*.ts.net`），需用户 Tailscale 登录。
- SQLite 落 VM 持久盘；备份用 GitHub 私有仓库（需 fine-grained PAT，用户创建一次）。
- 搭建更长、需 VM 运维；适合预算极紧且能接受容量风险。

## 3. 已否决路径（避免重复踩坑）
Render 免费 512MB 装不下 torch+storm；PythonAnywhere 磁盘不足；Vercel/CF 无 Python 子进程长任务；
云主机为临时 FaaS 沙箱（会话结束回收，禁当生产）；HF Static 无算力；ClawCloud 免费需 GitHub 账龄>180 天（账号约 137 天不合）。

## 4. 任务卡同步协议（云端↔本机执行 Agent）
- 云端：`GET /api/taskcards/pending`（须登录）→ 待执行/执行中清单。
- 本机执行 Agent：经 HTTPS+令牌拉取 pending → 写入本机 vault `50_解决区/任务卡/` 与 `_系统迭代/待执行任务卡.md` inbox →
  `POST /api/taskcards/{name}/claim` 标记执行中 → 完成后 `POST /api/taskcards/{name}/writeback`（status+record）。
- 云端不写本机 Obsidian、无任意命令执行接口；不伪造"已交接"。

## 5. 验收口径（逐项给证据，跨网络/手机标"待用户终验"）
1. 本机关闭 8600 后公网仍可用。2. 历史记录恢复（45 条 legacy + 新会话）。3. 访客仅虚构示例、真实数据登录后可见。
4. 公开仓库/Pages 无密钥与个人数据（secret scanning + 人工扫描）。5. CORS 精确 origin 不带凭证通配。
6. 任务重启恢复 interrupted。7. 任务卡真实领取/回写路径。8. 真实引擎端到端产出。9. Pages deployment 成功后才报最终 URL。
10. 手机/跨网络终验由用户做。11. 回执写 `_系统迭代/`，未来预期仅有证据才勾选，不写"用户验收通过"。
12. 自审给通过/附条件通过/不通过。

## 6. 休眠/冷启动/上限交代（免费实例规则）
- HF cpu-basic：48h 不活动休眠；访客自动唤醒；冷启动约 1–2 分钟（镜像含 torch，启动加载嵌入模型）。
- 并发：单实例；圆桌单会话；任务限流 5/小时，聊天 30/分钟，登录 5/分钟。
- 持久化窗口：写后即时 push + 45s 兜底，极端崩溃最多丢最近 45s 未同步写入（已落本地盘的部分重启可恢复）。
